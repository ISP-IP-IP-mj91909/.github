<h2>批量买的核心不是单价，是「同段」</h2>
<p>买单条地址时，你只关心它能不能用。买十条以上时，多了一个更重要的变量：这些地址是不是同一个网段、同一条上游。同段的地址归属一致、路由一致、延迟接近，多个身份放在同一个业务里不会出现「一个在纽约一个在洛杉矶」的落差；跨段拼凑的地址便宜，但一致性差，出问题时也难以统一处理。</p>
<p>所以询价时第一句话不该是「十条多少钱」，而是「这十条能不能同段」。愿意提供同段资源的服务方，通常资源掌控力更强；只能给跨段的，多半是转售拼接。</p>

<h3>阶梯单价：注意折扣的触发点</h3>
<p>多数服务方的折扣按数量分档，例如五条、十条、二十条各有一档。采购时容易犯的错是为了凑下一档多买几条闲置地址。判断标准很简单：多买的那几条，如果三个月内用不上，折扣带来的节省抵不过闲置成本。宁可少买，需要时同段追加。</p>
<h3>套餐包：看清「超量」怎么算</h3>
<p>套餐包看着省事，但要问清三件事：超出部分按什么价格计、未用完是否可结转、能否中途调整档位。第三条最关键——业务量变化时，不能调整的套餐会变成负担。</p>
<h3>基础费加地址费：适合有明确配置需求的团队</h3>
<p>这种方式下，服务器配置与地址数量分开计价，灵活度高。要确认基础费包含多少带宽、是否含基础地址、追加带宽怎么收费。三项不清楚，最后的账单常常超出预期。</p>

<h2>批量采购前先算清楚数量</h2>
<p>算法不是「有多少账号买多少条」，而是「有多少个必须独立的身份」。同一主体的多个账号、同一业务的不同环节，往往可以共用；真正需要独立的是那些一旦关联就会同时受损的身份。</p>
<p>算出基数后，加百分之二十的余量用于替换与测试。余量不宜过多，太多会拉高单位成本，也会让管理变复杂——每条地址都需要记录、巡检、核对，管理成本随数量线性上升。</p>

<h2>套餐配置里容易被省略的部分</h2>
<p>带宽。批量地址共享同一条链路时，总带宽是固定的，地址越多，单条可用带宽越少。做直播或多路视频的业务要提前算，别等上线才发现不够。</p>
<p>IP 段的可用性。一批地址里总有几个因为历史原因状态不佳。采购时可以要求「首批可用率」的约定，例如十条里至少有九条在验收时可直接使用。没有这条约定，验收时遇到两三条不可用，往往只能自己消化。</p>
<p>更换政策。批量场景下地址出问题的概率更高，更换次数与响应时限必须写清。按条更换还是按批更换、是否收费、多久完成，三项都要落到书面。</p>

<h2>议价的现实空间</h2>
<p>这个行业的毛利结构决定了议价空间主要在服务内容上，而不是单价上。与其硬压价格，不如争取三样东西：免费试用期延长、更换次数增加、同段追加的价格锁定。这三项对长期使用的价值远高于省下的那点月费。</p>
<p>如果对方在价格上让得特别多，要警惕是不是在独享程度或带宽上做了减法。地址资源有硬成本，明显低于市场的报价必然在某处缩水。</p>

<h2>验收：批量场景要抽样</h2>
<p>十条以内逐条验；十条以上按比例抽样，但核心业务用的地址必须逐条验。验收内容四项：ASN 与归属、出口回显、独享情况（同时在线测试）、延迟与稳定性。抽样结果异常时，扩大抽样范围，不要用「个别问题」搪塞过去。</p>
<p>验收记录要留档，包含验收时间、验收人、每条地址的结论。这份记录在后续纠纷中是唯一依据。</p>

<h2>常见问答</h2>
<h3>买得越多单价越低吗</h3>
<p>通常如此，但折扣幅度有限，且以放弃灵活性为代价（长周期、不可退）。算总成本时要考虑闲置与管理成本，不要只看单价。</p>
<h3>能不能先买五条，以后追加到十条</h3>
<p>可以，追加时确认是否同段。跨段追加会破坏一致性，如果一开始就有扩到十条的计划，直接问清追加政策比事后补更省事。</p>
<h3>批量地址能分给不同国家吗</h3>
<p>可以，按国家分别计价，价格差异较大。多国混合采购时，管理复杂度上升，建议按业务区域分组记录。</p>
<h3>套餐里没用完的地址能退吗</h3>
<p>多数不支持按条退订，或仅在特定周期内可调整。采购时把这条问清，避免业务收缩时被闲置成本拖住。</p>
